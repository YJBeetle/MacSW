# MacSW

1. Read `references/local-connection.md` if present. Use its recorded MacSW launcher and container/endpoint. If it is absent, use `/Applications/MacSW.app/Contents/MacOS/swcli` with its defaults. If the recorded installation moved or no longer matches the target, re-establish the connection before acting.
2. Check `version --json`, `daemon status --json` and `capabilities --json`. Use the same connection for subsequent commands. Require a successful status with `result.host_connected=true`, `result.worker_alive=true`, `result.recovery_required=false` and a non-null `result.host` before CAD operations. Request `capabilities --operation NAME --json` for the operation contract. A failed request does not establish that a document or feature is absent.
3. For “current file”, start with `document inspect --document active --json`. For a named file, use `document list --json` to identify an already-open document. Match paths and use explicit document IDs for multi-document work. Open or import only as needed, with read-only access where supported for inspection. Use the launcher's native path translation rather than assuming a `Z:` mapping.
4. Use the advertised typed command where it covers the task. Read [the bundled usage guide](references/usage.md) for request schemas, document targeting, leases, geometry and export workflows. Inspect native state before editing and verify the actual result before reporting success. If a command fails after starting an edit, inspect for partial changes before any retry.

For MCP setup, read [the packaged MCP guide](references/mcp.md). Configure the actual App's `Contents/MacOS/swcli` with arguments `mcp serve`; its native Python includes the optional SDK and the wrapper supplies `SWCLI_DAEMON_UTILS` pointing at the App’s shell daemon utilities. The endpoint and `MACSW_WINEPREFIX` must match the selected connection. The five MCP tools are `status`, `daemon_start`, `daemon_stop`, `capabilities` and `execute`. Tool discovery and `status` never start Wine/SW; use `daemon status --details --json` for the same read-only observations from CLI. Unknown process ownership and startup-cached visibility stay explicitly unknown/stale.

When a CAD task needs a stopped local daemon, use explicit `daemon_start` (MCP) or `daemon start` (CLI) within the task's authority, or use the MacSW menu. Starting daemon and SW may take several minutes; await readiness and inspect status after a timeout rather than starting again. Python parses all public CLI arguments; the App’s daemon utilities select Wine/Windows Python, not the MCP client's interpreter. Typed document commands do not start a daemon implicitly. At task completion choose whether to retain the host or explicitly stop it based on the user's stated preferences and follow-up work. `daemon_stop` is an MCP tool; `daemon stop` is the CLI equivalent. Both affect all clients on the endpoint and refuse shutdown of an owned host with open documents; MCP disconnect leaves the host running. With explicit lifecycle authorization, use `--attach-existing` to share a running instance. For an existing daemon with a disconnected host, recovery uses `daemon restart`, subject to the same authorization. Keep unsaved documents and existing instances intact. If process or approval checks block a lifecycle action, stop and use the menu or the normal approval mechanism.

The daemon's `tray` setting is separate from the SW window's `visible` setting. Its default `auto` keeps the Windows notification icon off under Wine; it does not control MacSW's native menu-bar icon. The MCP guide describes explicit `tray` selection.

## When the CLI has a coverage gap

If the capability catalog confirms the needed operation is missing or its documented scope excludes the task, continue with the [official SOLIDWORKS API workflow](references/solidworks-api.md). The bundled usage guide describes the typed CLI boundary. Use this separate route only for the uncovered capability. A timeout, access refusal, stale handle, document lease conflict, or failed typed operation must be diagnosed through its own path.
